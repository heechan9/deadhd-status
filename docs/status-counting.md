## 자동 조회와 집계

완료 규칙의 `subtasks`는 부모 카드 승인 조건이며 `milestones`는 별도 참고 하위 진행이다. 참고 진행은 상세·요약에 표시하되 부모의 완료 조건이나 필수 분모에 추가하지 않는다. `submission-team-intake`는 원래 정식 팀원 내부 1차 자료 취합 기준을 유지하고 전체 명단·접수 목록 대조를 기다린다. 외부 지원 최종 실행·추가 본인 검토·계약 채택은 별도 기록이다. `n-web`은 U01 고정본의 6조합 브라우저 하위 검토를 인정하되 최종 시연·JSON 다운로드는 미확인으로 유지한다. `c-ulsan`은 최종 원고의 사용 제외·한계 처리 확인이며 기관 원문 정정을 강제하지 않는다.

카드에 연결된 PR 의 열림·Draft·병합·CI 조회 결과는 카드 본문과 증거 링크에 표시한다. 카드 `state` 는 `content/<slug>.completion.json` 규칙으로만 바뀌며, 자동으로 완료가 될 수 있는 것은 '코드 반영(main 병합)'을 명시한 카드뿐이다. 현재 그 카드는 모두 `after-submission` 이라 필수 분자·분모에 영향이 없다. 필수 카드는 병합·CI 만으로 완료가 되지 않으며(연구 성과·본인 확인·계약 채택·최종 제출), 복합 필수 카드의 일부 완료는 '부분 완료'로 표시할 뿐 분자에 넣지 않는다. `countScope`·분모는 자동으로 바뀌지 않고 이 문서의 분류는 수동 검토로만 바뀐다. 조회 실패·오래된 기록은 새 완료를 만들지 않는다(이미 정리된 완료는 유지하되 '자동 확인 불가'를 표시). 조회 실패·오래된 기록·`curatedAt` 경과를 알리는 자동 항목(`pr-live-failed`, `curated-stale`)은 `countScope` 가 없어 필수 집계에 들어가지 않는다.


## 2026-10-30 정정: 원래 13개 점검표와 누락된 ACK 확인 복원

원래 진행 막대·분모 13을 제거하지 않는다. 표시는 **기존 13개 점검표 확인 완료(ACK+프로젝트 포함)**이며 연구 완성률이 아니다. 개발·제작·프로젝트 제출의 세 근거 그룹은 보충 정보다.

누락된 사용자 확인을 연결했다: ACK 논문 최종본 제출(2026-10-18 KST), 발표자 등록(2026-10-20 KST), ACK 영상 제출(2026-10-21 KST). 최종본·등록 부모 카드와 영상 부모 카드는 제출 이벤트 확인 기준으로 완료되어 기존 점검표는 9/13이다. 영상의 형식 준수는 제출 여부와 다른 검증이므로 참고 조건으로 보존한다. 공식 접수증·제출 파일 해시·실제 결제 완료는 독립 검증 완료로 바꾸지 않는다. 공개 페이지에는 확인 날짜와 근거 종류만 기재하고 대화 원문·개인 이름·접수번호는 게시하지 않는다.

남은 네 부모 항목은 프로젝트 최종 제출, 과거 팀 접수 명단 대조, 원문 정합성 최종 대조, 실제 웹 QA의 **확인 미완료/일부 확인**이다. 과거 팀 접수 명단 대조가 남았다고 최신 main 통합이 빠졌다는 뜻은 아니다.
